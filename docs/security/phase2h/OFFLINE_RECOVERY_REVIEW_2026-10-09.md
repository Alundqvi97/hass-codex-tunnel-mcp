## Static security review (without kernel firewall or guest execution)

| Question | Offline conclusion | Confidence / remaining proof |
|---|---|---|
| Localhost OUTPUT rejection | Original QEMU-UID OUTPUT chain rejected all `127.0.0.0/8` destinations; this could reject local health-check replies generated by QEMU's TCP listener | **Plausible hypothesis, not observed root cause** |
| Narrow proposed fix | An `-o lo -d 127.0.0.1/32 -p tcp -m conntrack --ctstate ESTABLISHED -j ACCEPT` rule precedes private/loopback rejects. For ordinary locally initiated TCP host-forward connections, SYN is from the test process; QEMU's reverse SYN-ACK/replies can match ESTABLISHED once conntrack sees the reply. QEMU-originated NEW connections to host localhost remain blocked by subsequent CIDR rejects | **Conditionally sound model; NOT live tested**. Depends on conntrack classification, actual interface/socket behavior and rule insertion/success |
| Guest-to-host bypass | QEMU user-mode networking exposes a virtual host gateway (normally `10.0.2.2`). It is not an independent network namespace; guest-initiated traffic becomes host-side QEMU-owned sockets. Output owner rules are essential. No `restrict=on` is set, and public IPv4 80/443 is permitted to any non-blocked address, not only official bootstrap domains; an address not in private ranges may still belong to a host-accessible service | **Not a complete hard isolation guarantee**. Do not introduce broad loopback permits; use bounded socket/egress negative tests in a future approved isolated runner |
| Host-to-guest ingress | Four TCP hostforwards are explicitly bound to `127.0.0.1` on the runner (18123, 18124, 14357, 19583). QEMU documentation supports binding `hostfwd` to that interface | **Configured, not tested via host listener inspection or negative off-host attempt** |
| IPv4/IPv6 | `ip6tables` owner chain ends with REJECT for QEMU, but QEMU `-netdev user` defaults to both IPv4 and IPv6 enabled; no `ipv6=off` guest-network option. IPv4 rejects named private/link-local/multicast/bogon CIDRs but allows general public web/DNS/NTP. ### External source checks

- [QEMU networking and `hostfwd`, `ipv6`, `restrict`](https://www.qemu.org/docs/master/system/qemu-manpage.html): `-netdev user` uses user-space NAT; absent explicit protocol selection, both IPv4/IPv6 are enabled. `restrict=on` would block required first-boot egress and is not a drop-in fix.
- [QEMU user-mode guest gateway and DNS](https://www.qemu.org/docs/master/system/devices/net.html): virtual host `10.0.2.2`, DNS `10.0.2.3`.
- [HAOS partition specification](https://developers.home-assistant.io/docs/operating-system/partition/): data filesystem label `hassos-data`, mounted `/mnt/data`, contains Supervisor and add-on data.
- [Official Home Assistant installation guidance](https://github.com/home-assistant/home-assistant.io/blob/current/source/_includes/installation/operating_system.md): initial internet needed to download Core.
