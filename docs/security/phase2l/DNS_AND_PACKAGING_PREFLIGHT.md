## Network algorithm and remaining runtime proof

1. Select only one explicitly reviewed public IPv4 resolver. Fail closed for local DNS stubs, other loopback, RFC1918, link-local, CGNAT, IPv6, malformed or multiple entries.
2. Determine the actual libslirp host-side resolver and compare to that address. A claimed upstream in JSON is not attestation. An unknown or changed route BLOCKS.
3. Future owner-UID Linux OUTPUT policy must permit UDP **and TCP** DNS port 53 to exactly the reviewed resolver. Everything else defaults to REJECT; no general localhost/private-network exception.
4. Resolve reviewed registry/core bootstrap FQDNs dynamically under that resolver with address/TTL/redirect review, and allow only verified public IPv4 destinations for required TCP 443 (and 80 when justified). Do not guess static CDN IPs. Neither FQDN-to-IP binding nor registry redirects are proven yet.
5. Establish actual NTP/time-sync transport and approved public endpoint, with narrowly scoped UDP 123 only if needed. Actual time synchronization remains NOT VERIFIED.
6. Keep guest ipv6=off and an independent host IPv6 reject; QEMU user-mode NAT still creates host-owned sockets. Preserve narrow ESTABLISHED loopback reply handling, private-network denials, and 127.0.0.1-only forwarded ports. Kernel owner/conntrack/IPv6 isolation and host-to-guest/guest-to-host negative tests are NOT TESTED and require separate approval.
7. A future approved runner-only observer must produce trustworthy resolver-route, destination and firewall-readback receipts before any VM. Unknown state or mismatched rules aborts. It has not been implemented or authorized here.
